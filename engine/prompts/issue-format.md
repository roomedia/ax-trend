# 이슈 본문 형식 (풍부한 다이제스트 — 과요약 금지)

## 제목

`config.yaml`의 `issues.language` (기본 한국어). 형식: 핵심 엔터티 + 사건 + 날짜/출처.
예: "Mistral, 신규 AI 모델 발표 예고 — 중국 모델 대비 사이버 분야 우위 주장 (10/6, Reuters)"

## 본문

아래 섹션 구조로, `config.yaml`의 `issues.body_words`(기본 300~450단어)를 목표로 한다.
**이 이슈만 읽고도 내용을 파악할 수 있을 정도로 구체적으로** 쓴다. 3~5줄 압축 요약은 금지.
원문에 없는 내용은 창작하지 않는다.

1. **핵심 사실** (5~8개 불릿): 누가/언제/어디서/무엇을/얼마나.
   수치·날짜·인명·제품명·금액은 원문 표기 그대로 적고, 각 불릿에 출처 매체를 병기한다.
2. **배경·맥락** (2~4문장): 이 뉴스가 나오게 된 흐름, 직전 발표·사건과의 관계.
3. **아직 안 밝혀진 것 / 쟁점** (2~4개 불릿): 미공개 정보, 상충되는 보도, 과장 가능성.
   불확실하면 "미확인"으로 명시하고 추측은 금지.
4. **왜 중요한지** (2~3문장): `config.yaml`의 `reader` 관점에서의 실무적 함의.
5. **핵심 링크**: 원문 1~3개 (날짜 표기). GitHub 트렌딩 후보는 레포 URL을 반드시 포함.
6. **관련 이슈**: 군집 판정 과정에서 찾은 같은 엔터티/주제의 기존 이슈를 `#번호` 형태로 최대 5개 링크. 중복은 아니지만 주제가 이어지는 것(이전 버전, 같은 주체의 다른 발표, 관련 기술) 포함. 예: `- #3021 — Reflection Beam ...`. 관련 이슈가 없으면 이 섹션 생략.

## 핑거프린트 (필수)

본문 끝에 멀티 에이전트 중복 방지용 기계 판독 핑거프린트를 삽입한다:

```html
<!-- ax-events: 토큰1,토큰2,토큰3 -->
```

토큰 규칙: 핵심 엔터티(회사명/제품명/모델명/주제 키워드)를 단일 토큰으로 분해.
소문자 영문 + 한글 원형, 공백·특수문자 제거, 엔터티당 1토큰.
예: `<!-- ax-events: reflection,beam,리플렉션 -->`
