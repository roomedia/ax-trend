# AX Trend Engine — 한국형 AI 트렌드 다이제스트 엔진

> 어떤 에이전트에서든 실행 가능한, 프롬프트 기반 AI 뉴스 선별·발행 파이프라인.
> 수집 → 채점 → 군집 → 발행. 코드는 얇고, 판단 기준은 전부 프롬프트에.

AX Trend Engine은 특정 에이전트 프레임워크에 종속되지 않습니다.
웹 검색과 `gh` CLI만 쓸 수 있으면 — Muse, ChatGPT, Claude Code, Codex, Gemini CLI, 로컬 스크립트 —
무엇이든 실행 주체가 될 수 있습니다. 판단 로직은 `prompts/` 디렉토리의 마크다운 프롬프트에 들어 있고,
임계값은 `config.yaml`에 들어 있습니다. **프롬프트를 고치면 동작이 바뀌고, 코드를 고칠 일은 없습니다.**

이 엔진은 2026년 10월부터 실제 운영 중인 다이제스트 파이프라인에서 추출한 것으로,
발행된 이슈 3,000여 건과 그 과정에서 얻은 실패 교훈(`LESSONS.md`)이 녹아 있습니다.

## 왜 한국형인가

- **한국어 이슈가 기본 산출물.** 제목·본문 모두 한국어. 원문은 영어·중국어·일본어여도 독자가 읽는 건 한국어 다이제스트.
- **한국 독자 관점의 채점.** `selection-score.md`의 독자 정의(`reson` 축)를 바꾸면 어떤 독자층이든 대응 가능. 기본값은 한국 개발 조직의 실무자.
- **한국 시간대 기준 신선도.** KST 기준 48시간 이내 원문만 발행. 검색 스니펫 날짜가 아닌 원문의 `datePublished`를 직접 검증.
- **한국 AI 업계 소스를 1급으로.** 국내 매체·국내 기업 발표를 T1(공식 1차) 등급으로 올릴 수 있는 소스 등급 체계.

## 파이프라인

```
┌────────┐   ┌────────┐   ┌──────────┐   ┌────────┐   ┌────────┐
│  수집  │ → │  채점  │ → │  군집   │ → │  발행  │ → │  보고  │
│ collect│   │ score  │   │ cluster  │   │publish │   │report  │
└────────┘   └────────┘   └──────────┘   └────────┘   └────────┘
  웹 검색      독립 2회      이벤트 단위    GitHub      요약
  + GitHub     0~100점      같은 사건/     이슈 생성    전달
  트렌딩       등급별        후속/별개
              임계값        판정
```

1. **수집** — 최근 N시간 내 AI 실무 뉴스 검색 + GitHub 트렌딩(일간·주간) 스캔. 정치·정책 뉴스는 수집 단계에서 제외.
2. **채점** — `prompts/selection-score.md` 기준으로 후보마다 **독립 2회** 0~100점 채점. 두 회차 합이 `2 × 임계값` 이상만 통과. 임계값은 소스 등급별: T1(공식 1차)=60, T1.5=65, T2(미디어·개인·보도자료 재배포)=76.
3. **군집** — 1차 토큰 검색(엔터티를 단일 토큰으로 분해해 `gh search issues` + 최근 open 100건 직접 스캔) 후, 2차로 `prompts/event-clustering.md`의 모델 판정: **같은 사건 / 후속(새 사실 있음) / 별개**. 애매하면 합친다.
4. **발행** — `prompts/issue-format.md` 형식으로 이슈 생성. 이슈 본문 끝에 `<!-- ax-events: 토큰,토큰 -->` 핑거프린트 삽입 (멀티 에이전트 중복 방지용).
5. **보고** — 새 이슈가 있을 때만 다이제스트 전달. 없으면 조용히 종료.

## 여러 에이전트가 같은 레포에 써도 중복이 안 생기는 구조

여러 사람이(여러 에이전트가) 같은 레포에 이슈를 올려도 "하나의 사건 = 하나의 이슈"가 깨지지 않도록 3중 장치를 둡니다.

**① 발행 전 핑거프린트 대조 (1차 방어)**
모든 발행 이슈는 본문 끝에 기계 판독용 핑거프린트를 포함합니다:

```html
<!-- ax-events: reflection,beam,리플렉션 -->
```

발행 직전, 에이전트는 `scripts/fingerprint.sh`로 최근 open 이슈 100건의 핑거프린트를 읽어 후보 토큰과 대조합니다.
GitHub 검색 인덱스는 신규 이슈 반영이 늦으므로, **검색 API가 아닌 이슈 목록 직접 스캔**이 정석입니다.

**② 이벤트 군집 판정 (2차 방어)**
토큰이 겹치지 않아도 같은 사건일 수 있습니다(번역 제목, 다른 키워드).
`prompts/event-clustering.md`가 모델에게 "같은 사건인지, 새로운 사실이 있는 후속인지, 별개인지"를 판정시킵니다.
애매하면 합치는 쪽으로 — 의심스러울수록 발행하지 않습니다.

**③ 토픽 레인 분담 + 사후 정리 (3차 방어)**
- 동시에 도는 에이전트는 `config.yaml`의 `lanes`로 담당 주제를 나눕니다 (예: A=모델·연구, B=도구·오픈소스, C=업계·트렌딩). 레인이 달라도 사건이 겹치면 ①②가 잡습니다.
- 잔여 중복은 레포의 `deduplicate-issues` GitHub Action이 정규화 제목 기준으로 자동 정리합니다 (이슈 생성 시점에 트리거 + 정기 실행).

```
에이전트 A ─┐
            ├→ 핑거프린트 대조 → 군집 판정 → 이슈 발행 ─→ Action이 잔여 중복 정리
에이전트 B ─┘   (발행 직전 read)   (모델 판정)
```

## 빠른 시작

```bash
# 1. 설정 복사
cp engine/config.example.yaml engine/config.yaml
# 2. 독자 정의·소스 등급·임계값·레인을 내 조직에 맞게 수정
# 3. RUNBOOK.md를 에이전트에게 그대로 전달
```

에이전트에게 이렇게 지시하면 됩니다:

> `engine/RUNBOOK.md`를 읽고 한 사이클 실행해. 설정은 `engine/config.yaml`을 따라.

필요한 것: 웹 검색 능력, `gh` CLI (repo 스코프 인증), 대상 레포 쓰기 권한.

## 디렉토리 구조

```
engine/
├── README.md                  # 이 문서
├── RUNBOOK.md                 # 에이전트용 실행 절차 (그대로 전달)
├── config.example.yaml        # 설정 템플릿 (복사해서 config.yaml로)
├── LESSONS.md                 # 실운영 실패 교훈 모음
├── prompts/
│   ├── selection-score.md     # 선별 채점 프롬프트 (독립 2회, 등급별 임계값)
│   ├── event-clustering.md    # 이벤트 군집 판정 프롬프트
│   └── issue-format.md        # 이슈 본문 형식 (300~450단어 다이제스트)
└── scripts/
    └── fingerprint.sh         # 최근 open 이슈 핑거프린트 스캔
```

## AIHOT과의 관계

설계에 AIHOT([KKKKhazix/AIHOT](https://github.com/KKKKhazix/AIHOT))의 아키텍처를 차용했습니다:
독립 2회 채점, 소스 등급별 임계값, 이벤트 단위 군집화, 프롬프트 외부화.
차이점은:

| | AIHOT | AX Trend Engine |
|---|---|---|
| 출력 언어 | 중국어 | 한국어 |
| 실행 주체 | 전용 Node.js 서버 | 어떤 에이전트든 (프롬프트만 있으면 됨) |
| 저장소 | PostgreSQL | GitHub 이슈 그 자체 |
| 멀티 라이터 | 단일 운영자 | 핑거프린트 + 레인 분담으로 다수 에이전트 대응 |
| 신선도 | 일간 발행 | 원문 `datePublished` 직접 검증, 48시간 컷 |
